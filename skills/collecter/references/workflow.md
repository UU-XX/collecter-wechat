# Collecter Skill 工作流

## 独立分发约定

Skill 随包提供自身需要的 Python 读取、导出和统计脚本，业务能力与 Python / CLI 共用核心实现，运行不依赖另装 CollecterCLI，不启动交互式终端菜单或桌面客户端。

随包入口为 `scripts/collecter.py`，核心模块位于 `scripts/engine`，读取组件位于 `scripts/reviewed-tools`。使用 Python 3.12 安装 `requirements.txt` 后运行，不调用 CLI 程序或交互菜单。

以下命令在 Skill 根目录执行，`python` 表示安装依赖后的解释器。示例路径与会话编号需要换成用户的实际选择：

```powershell
python -B scripts/collecter.py accounts
python -B scripts/collecter.py sessions --account 'D:\微信数据\账号\db_storage'
python -B scripts/collecter.py export --account 'D:\微信数据\账号\db_storage' --conversation '实际会话短编号' --start '2025-01-01' --end '2025-01-31' --output 'D:\聊天导出'
python -B scripts/collecter.py plan --input 'D:\聊天导出\实际结果目录'
python -B scripts/collecter.py chunk --input 'D:\聊天导出\实际结果目录' --day '2025-01-01' --index 1
python -B scripts/collecter.py report --input 'D:\聊天导出\实际结果目录' --output 'D:\聊天报告'
```

脚本标准输出为 JSON，进度写入标准错误。首次获取密钥需要本次授权时，才在 `sessions` 或 `export` 上添加 `--allow-memory`；批量会话重复 `--conversation`，视频和附件分别使用 `--videos`、`--files`。

`plan` 返回全部有效日期与片段数。逐日按 `1..chunks` 读取 `chunk`，宿主分析每段后形成当日总结，全部日期完成后再综合总体总结。`plan` 中的请求估计来自共用引擎，不代表宿主已经发生的模型调用数。

完整 Skill 发行包应提供：

- 本机账号和会话选择所需的脚本入口。
- 有明确账号、会话、时间范围和输出目录的非交互导出入口。
- 读取已有导出、分页检索和生成本地统计的入口。
- 固定版本读取组件、来源、校验值及第三方许可。
- Windows、Python 与运行依赖说明。
- 能被宿主读取的结构化结果和受控错误码。

## 选择与读取

优先沿用用户明确指定的账号、会话和范围。需要列出账号或会话时，仅通过随包脚本限定的本机入口执行；显示名称与编号，避免重名误选。

内存读取授权仅用于本次数据库密钥获取，缓存足够时不要主动扫描。不要为了提权自动重启微信、关闭进程、修改原数据库或换用未知来源组件。

## 导出与核对

沿用核心引擎的新目录策略、身份校验与去重方式。核对 `采集说明.json`、`records.sqlite3` 与结果文件是否一致，区分数据读取完成、格式文件生成完成与历史完整性。

用户要求仅导出时，完成到此即可，不因宿主具备 AI 能力就默认分析全部聊天。

## 宿主分析

用户需要分析时，说明当前宿主将读取哪些内容及模型处理位置。默认使用宿主已有能力，不要求用户额外配置 Collecter 的模型 API。

按北京时间逐日处理全部有效正文。记录多时按连续片段读取，不静默只取开头、末尾或抽样消息。每段保留记录编号、时间、发送人及正文，用简短事实摘要连接上下文。

将片段摘要合并为完整日总结，再按时间顺序合并所有已完成日期。输入超过宿主上下文时继续拆分，不以截去后面的记录作为完成方式。

每日总结保存到 `每日总结/日期.md`，全部处理完成后保存 `总体总结.md`。总结只保留主要话题、重要观点和明确结论，不单列待办或行动建议。

记录已经处理的范围，区分宿主实际保存的进度与可自动恢复的能力。宿主中断或脚本失败时保留已有结果，不能将一次手工记录进度描述为已经实现可靠的自动断点续跑。

## 交付

给出本地结果路径、已处理天数或范围、总体总结是否完成，以及影响结果的解析或读取问题。诊断不附带聊天正文、思考过程、密钥或令牌。
